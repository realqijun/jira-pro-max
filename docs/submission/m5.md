# Milestone 5 - MVP and future expansion

## MVP

The MVP is the smallest coherent loop from planning to remembered reasoning.
Everything below is live at https://jira-pro-max.vercel.app.

| Area                     | What ships                                                                                                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project management       | Projects, Tasks, Milestones, Dependencies, per-Project statuses, Risks, People and Teams; board, list, Timeline and Calendar views; command palette; field-by-field History |
| Evidence                 | Pasted notes, transcripts and uploaded files (PDF, Word, text), with text extraction, Labels and links to Tasks, Risks and Milestones                                       |
| Decision Memory          | Decisions with citations, alternatives, Assumptions, supersession and a decision graph                                                                                      |
| Proposals from Evidence  | Every Evidence save or Comment triggers a background pass that proposes Decisions, Tasks and Milestones, each with a verbatim excerpt; the PM accepts, edits or rejects     |
| AI Assistant             | Project and workspace docks; 30 tools over the service layer; semantic Evidence search; cited "why did we" answers; approval cards for every write                          |
| Impact awareness         | Broken Assumptions raise an alert naming the downstream Decisions affected                                                                                                  |
| Concept Renders          | An image of the deliverable, drafted from up to three pieces of Evidence and generated only from the description the PM approved                                            |
| Bring your own model     | Per-User provider credentials (OpenAI, Anthropic, Google, any OpenAI-compatible gateway), encrypted at rest                                                                 |
| MCP                      | The same tools served at `/api/mcp` to Claude Desktop or Cursor with a personal API token                                                                                   |
| Collaboration and access | Email and Google sign-in, Project ownership, Participant messaging through invite links                                                                                     |
| Onboarding               | A sample Project seeded for every new User and a guided product tour                                                                                                        |
| Operational basics       | Responsive UI, landing page with SEO and Open Graph, PostHog analytics including LLM spans, Vitest and Playwright in CI                                                     |

## How we selected these features

We prioritized features that complete the core problem loop:

**capture source material -> structure the current work -> preserve a Decision -> retrieve the reasoning -> react when assumptions change.**

A feature was included when it did one of three things: completed that loop, made an AI action trustworthy enough to use, or was necessary for a usable multi-user Project.

- Evidence, Decisions, "why did we" and impact alerts are the loop itself.
- Proposals exist because the loop breaks if a PM has to type every Decision by hand; nobody maintains a decision log manually for long.
  Task and Milestone Proposals were added after the Decision pass, because the same meeting notes also hold the action items and a PM should not have to copy those out either.
- Approval cards, verbatim excerpts and citations exist because an Assistant a PM cannot verify is one they will not use for anything that matters.
- The sample Project and tour exist because the value only shows once a Project has Evidence and Decisions in it, and an empty workspace hides that.
- Renders were added for one audience: PMs on physical deliverables (a community centre, a pavilion) who need a picture for stakeholders early, before any design work exists.

Generic views, automation rules and integrations were deliberately left for later.
They are what competitors already do well (M1), and none of them completes the loop above.

## Future features

- Reusable Project and workflow templates, built from a completed Project's Decisions and Tasks.
- Importers for Jira, Asana, Google Docs and meeting platforms (Zoom and Teams transcripts straight into Evidence).
- Calendar, email and Slack integrations, so a Decision made in a thread becomes a Proposal.
- Team-level permissions and organization workspaces (today one User owns a Project).
- Health Briefings: a proactive weekly summary built on the deterministic read model in `workspace/queries.ts`.
- Outcome feedback linking Decisions to delivery results, so "did this Decision work?" becomes answerable.
- A tighter item extractor, measured against the 12 item eval cases (M11 addendum lists the first candidate change).
- Usage-based or team-based billing and enterprise controls (M6).
