# Milestone 6 - Monetization and pricing strategy

The current release is a free research preview, and the landing page says so.
This removes friction while we validate whether the Evidence-to-Decision workflow solves a sufficiently painful problem.
No checkout is implied.

## Proposed pricing

| Tier       |     Indicative price | Intended customer                          | Scope                                                                                                 |
| ---------- | -------------------: | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Preview    |                 Free | Individual evaluators and small Projects   | Core Project management, 3 Projects, Assistant at 50 turns a day, Proposals, Decision Memory, BYO key |
| Team       | US$12 per user/month | Small professional teams                   | Unlimited Projects, shared Projects, higher Assistant and Render limits, templates, MCP               |
| Business   | US$25 per user/month | Multiple teams                             | Organization workspaces, permissions, audit export, integrations and priority support                 |
| Enterprise |               Custom | Organizations with compliance requirements | SSO, retention controls, dedicated limits, vendor-direct or private model deployment                  |

Prices are hypotheses to test with early users, not a finalized commercial plan.

## What it costs us to serve a User

These are measured per-unit costs from the eval harness (M9, M11, M12), not estimates.

| Unit                                             | Measured cost            | Source                                                       |
| ------------------------------------------------ | ------------------------ | ------------------------------------------------------------ |
| One Assistant answer turn, `gemini-2.5-flash`    | about US$0.0018          | 20-case answer suite, gateway-reported cost                  |
| One Proposal pass over 9 sources (Decision call) | US$0.0043                | M12, batched pass                                            |
| Item call beside it (Tasks and Milestones)       | about US$0.0002 per case | M11 addendum, `gpt-4o-mini` at list price                    |
| A repeat pass with no new text                   | US$0                     | Content-hash idempotency (M12)                               |
| A Render                                         | US$0 to us               | Pollinations free tier; drafting runs on the Assistant model |
| Worst case per User per day at the 50-turn cap   | about US$0.09            | `ASSISTANT_DAILY_TURN_CAP` x per-turn cost                   |

A realistic active PM (10 Assistant turns and 5 Evidence saves a working day, 22 days a month) costs about 220 x $0.0018 + 110 x $0.0045, roughly **US$0.90 a month** in inference.
Even a User who hits the daily cap every working day costs about US$2.
At US$12 a seat, inference is under 10% of revenue in the worst case, which leaves room for hosting (Vercel, Neon Postgres, Blob storage), analytics and support.

## Why this model fits

- A per-user team subscription is familiar to project-management buyers (M1: ClickUp, Asana and Monday all price per seat) and aligns revenue with the number of people receiving collaboration value.
- The free Preview supports product-led adoption: the value only shows once a Project has Evidence and Decisions in it, so a User must be able to try it on a real Project before paying.
- Higher tiers are justified by collaboration, governance and integrations rather than by hiding core Project data behind a paywall.
- Inference scales with usage, so the Preview carries fair-use caps (the daily turn cap already exists in code) rather than unlimited AI.
- Bring-your-own-key already ships (ADR 0011): a team on its own provider account moves inference cost off our books, and privacy-sensitive teams keep the model relationship in their control.
  That makes a lower "BYO key" seat price possible later without risking margin.
- The most important finding for pricing came from the model bake-off: model choice is an 8x cost lever for similar quality (M12).
  Pricing must assume a cache-friendly model; a tier that let every User pick an expensive, uncached model would need a usage surcharge.

## Factors that influenced the decision

| Factor          | How it shaped pricing                                                                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Production cost | Inference under US$1 per active User per month makes a seat price viable; storage and Postgres scale with Evidence volume, so large-file tiers are where limits belong |
| Perceived value | The value is time not spent reconstructing why something was decided during a handover; one saved hour a month exceeds the seat price for any PM                       |
| Competition     | Anchored between Asana Starter and Business pricing; we compete on memory, not on more views, so we cannot charge a premium over incumbents until the memory is proven |
| AI inference    | Measured, capped per User per day, and removable through BYO key                                                                                                       |
| Trust           | We would never sell Evidence or Project content; the moat is trust and accumulated memory (M3), so no revenue stream may depend on the data itself                     |

## Revenue streams

1. Per-seat subscriptions (primary).
2. Usage-based overage for heavy Assistant or Render use above the tier cap.
3. Paid integrations and importers (Jira, meeting platforms).
4. Migration and onboarding services for teams moving an existing decision log in.
5. Enterprise support and private or vendor-direct model deployment.
