## AI interaction patterns, and why each one is here

| Pattern                                             | Where                                                                 | Why this pattern                                                                                                                                                                                                                                                        |
| --------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool-calling agent loop                             | `/api/assistant/chat`, `streamText` with `stopWhen: stepCountIs(8)`   | A PM's request ("plan the launch", "why did we move the date") needs several reads and writes whose order depends on what the earlier ones returned. A fixed pipeline cannot do that; the loop can, and it is bounded so it cannot run away.                            |
| Tools over a shared registry, never raw SQL         | `assistant/tools.ts` to `<feature>/service.ts`                        | The model is one more caller of the service layer, so its writes get the same ownership check, validation, transaction, Activity Event and domain event as a click in the UI (ADR 0007). The alternative - letting a model write - would put authorization in a prompt. |
| Retrieval over Project Evidence (RAG)               | `search/service.ts`, chunked embeddings, per-Project FAISS (ADR 0014) | Answers must come from this Project's documents, not from the model's memory. Chunk text is what the model quotes, and every match carries a ready-made citation.                                                                                                       |
| Deterministic read model beside retrieval           | `decisions/service.ts` `search`, `decisions/answers.ts`               | "Why did we" is answered from confirmed Decisions with their Sources, not from similarity. Embeddings rank; they do not decide what is a fact. Pending Proposals live in another table so retrieval cannot mistake them for Decisions.                                  |
| Structured output for extraction                    | `proposals/extract.ts`, `generateObject` + Zod                        | The output becomes rows. A schema removes parsing failures, and `trace.ts` then checks the content the schema cannot: every excerpt verbatim, every cited source real.                                                                                                  |
| Human-in-the-loop approval                          | `requiresConfirmation` tools, signed approval requests                | Deleting a Task and changing a Project are irreversible from the User's point of view, so the model proposes and the User approves (ADR 0011). Proposals use the same idea at feature level: a model-extracted Decision stays pending until a PM accepts it.            |
| Event-driven background work                        | `eventBus`, `after()`, proposal pass, Reflection                      | Extraction and memory-writing must not sit in the User's save or answer path. Failures are logged and never replace a delivered answer.                                                                                                                                 |
| Memory as versioned documents                       | Profile and Working Memory (ADR 0008 area)                            | Chat history alone grows without bound; a rewritten document keeps the useful part bounded and inspectable.                                                                                                                                                             |
| Deterministic reasoning where a model is not needed | `impact/subscriber.ts`, graph walks                                   | Breaking a contradicted Assumption and walking consequences is graph logic with a right answer. Using a model there would add cost and non-determinism to something that is already correct.                                                                            |
| External tool surface (MCP)                         | `/api/mcp` over the same registry                                     | Claude Desktop or Cursor can drive PrismPM without a second implementation of any tool. Confirmation-required tools are filtered out, because that adapter has no approval card.                                                                                        |

Patterns deliberately not used: no multi-agent orchestration (one loop with tools was sufficient and is far easier to audit), no fine-tuning (the behaviour needed is instruction-following over Project data, which prompts and tools deliver), and no vector store for anything except Evidence text.

## Framework and SDK selection

| Choice                                             | Alternatives considered                                             | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vercel AI SDK (`ai`, `@ai-sdk/*`, `@ai-sdk/react`) | LangChain / LangGraph, direct provider HTTP                         | The app already is a Next.js app, and the SDK covers exactly the seams needed: a tool loop with a step bound, `generateObject` with Zod, streaming into `useChat`, and signed approval requests for tool calls. LangChain adds an abstraction layer over prompts and chains that this project does not need - the orchestration lives in services, not in a chain. Direct HTTP would mean hand-rolling streaming, tool-call parsing and approval signing. |
| `mcp-handler` for the MCP endpoint                 | Hand-rolled Streamable HTTP, or an MCP server as a separate process | Keeps the protocol in one dependency and the tools in the app, so no tool is implemented twice and no internal call goes over HTTP.                                                                                                                                                                                                                                                                                                                       |
| Zod for tool inputs and extraction output          | JSON Schema by hand, TypeBox                                        | Already the validation library for server actions, so one schema shape serves the form, the action, the tool and the model.                                                                                                                                                                                                                                                                                                                               |
| `faiss-node` per Project                           | pgvector, a hosted vector database                                  | Kept the database migration surface small and the index scoped to one Project, which is also the authorization boundary. The trade-off and its limits are ADR 0014.                                                                                                                                                                                                                                                                                       |
| An OpenAI-compatible gateway for model choice      | One SDK per vendor as the deployment default                        | Model becomes configuration rather than code, which is what made the bake-off in [M9](m9-model-bakeoff.md) possible without touching `model.ts`.                                                                                                                                                                                                                                                                                                          |
